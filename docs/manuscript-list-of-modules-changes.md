## Quick list — what must be struck or reworded

**Remove these claims (deviations with written reasons, Appendix C of the memo):**

1. Any *doctor deletes student/patient record* point (M-01, M-05, M-07, M-08, M-09, M-12) — **C-1/C-4/C-5**.
2. *Admin deletes patient accounts* (M-01, M-02, M-19, M-20) — admin removal covers **staff accounts only**; patients self-delete — **C-2**.
3. *Admin/doctor can create, edit or delete consultations* as operator (M-14, M-15) — admin is read-only oversight — **C-11**.
4. *Admin authors/edits clinical recommendations* (M-13) — **C-7**.
5. *Patient can view doctor's recommendations* (M-13) — replaced by: patient views **published consultation progress notes** and system self-care tips — **C-6** (approved precedent).
6. *Admin can read patient–doctor messages* (M-16) — **C-8**; and any *delete chat messages* point for any role — **C-9**.
7. *Hand-compose / broadcast notifications* (M-17) — notifications are generated by database events/triggers — **C-10**.
8. *Edit or delete generated reports* (M-22) — reports are generated on demand, nothing is stored — **C-12**.
9. *Admin configures stress-test weights / model thresholds* (M-10, and the Detection settings in M-18/M-20) — weights are fixed versioned algorithm constants — **C-13**; the Detection settings tab, retention, anonymization, GDPR, 2FA, IP-whitelist and API-key controls were removed as unenforceable (**A-5**).
10. *Editable PSS-10 questions in the admin form* (M-06) — the built-in PSS-10 is **version-locked** (translated en/fil/ceb); the form's question editor is hidden for the Multi-Modal tool — **C-15**. Custom surveys are created as *Supplementary* tools.
11. *Standalone demo face scan* (M-09) — removed; face scanning happens only inside the assessment flow where results are saved (**A-9**).
12. *Consent records may be deleted* (M-04) — consent proof is never deleted — **C-14**.

**Rewrite these points:**

- **M-01 Delete (Admin):** "removes unapproved/staff accounts" (not students).
- **M-01 Delete (User):** "self-service account deletion".
- **M-03 Delete (User):** "clear health background by re-running setup" (no history table).
- **M-05 Update (Doctor):** "marks a result as *Reviewed* (persisted review status)".
- **M-05/M-07/M-08 Update (User):** "correction by retaking **before** submission — submitted data is immutable".
- **M-06 Create/Update (Admin):** "creates/edits supplementary survey tools (title, description, category, status, duration, questions)"; PSS-10 content is version-locked.
- **M-10 Create (Admin):** "authors assessment tool content; scoring weights are fixed algorithm constants".
- **M-13 Create (User):** "system-authored self-care tips".
- **M-17 Create (all roles):** "event-generated by database triggers on assessment, consultation and account events".
- **M-20 Update (Admin):** "applied settings only — system name, theme/density, high-stress alert gating, session timeout, password policy, data export".

**Add these points:**

- **M-05 ➕** Doctor: *Mark as Reviewed* persists across sessions (reviewed-at/by, appointment-linked write permission).
- **M-06 ➕** User: opens administrator-published *supplementary assessments* from the assessment hub and submits them as sessions.
- **M-10 ➕** The system computes **one canonical stress formula** shared by the mobile app, the result screens and the admin/doctor component charts (survey 50%, heart rate 20%, face 20%, reaction 10%; renormalized over available indicators).
- **M-09 ➕** Admin/Doctor: detected emotion label and scan confidence stored with each session and usable in filters/statistics.
- **M-03 ➕** Doctor: reads the student's self-reported health background (mental/physical conditions) in the case detail.
- **M-17 ➕** All roles: dismiss (remove) a notification from their own list.
- **M-04 ➕** Consent Management: a required consent checkbox now gates sign-up in both apps (mobile + web) and files a `registration` proof via a database trigger; the face-scan privacy sheet files a `face_scan` proof before the scan starts; administrators get a read-only consent register.
- **M-23 ➕** Activity Log: what was created/updated/deleted is recorded by database triggers (cannot be bypassed by either app) and shown to administrators in a read-only log view.

**Pending builds — only the optional, adviser-gated items remain (B-6):**

| Module | Pending item (optional — B-6, each needs an adviser decision) |
|---|---|
| M-02 / M-13 / M-06 | Admin contact-field correction (C-3); admin read of recommendations; admin item-level survey answers |
| M-01 | Mobile MFA panel |
| M-07 / M-08 / M-19 | Patient cancels own booking; admin cancels no-show (status changes only — no new deletion paths) |

*Phase 3 (M-04 consent records, M-23 activity log) is complete — do not describe these two as "in progress" any more.*

## Suggested summary paragraph (for the manuscript's implementation-status section)

> All 24 modules were audited cell-by-cell (operation × role) against the running
> implementation. Eleven defects were found and fixed (including non-persisting review
> state, a duplicated stress-scoring formula, unreachable supplementary assessments and a
> survey crash). Nine spec points were replaced with safer, clinically standard behaviour —
> most importantly, clinical records and recommendations are immutable and are never
> visible or deletable by non-clinicians — each with a written justification in the
> deviation log. Four modules were completed with additive, trigger-enforced builds
> (consent records, activity log, doctor's view of health background, notification
> dismissal); the consent and activity-log modules are written by database triggers and
> exposed through read-only administrator registers, and the remaining points are
> implemented as specified. A final batch of optional, adviser-gated refinements remains.
